# Building iRemote from source

This document covers a developer build. End users should grab a pre-built binary from the [Releases](https://github.com/jono-shaw/iRemote/releases) page instead.

## Prerequisites

- macOS 14 (Sonoma) or later.
- Xcode 15+ (or just the Command Line Tools — `xcode-select --install`).
- [xcodegen](https://github.com/yonaskolb/XcodeGen) — `brew install xcodegen`.
- The same runtime dependencies the app expects at launch:
  - PacketLogger (Additional Tools for Xcode).
  - whisper.cpp's `whisper-cli` (`brew install whisper-cpp`).
  - The Apple Bluetooth Logging Profile (see [README.md](README.md#requirements)).

## Building

```sh
git clone https://github.com/jono-shaw/iRemote.git
cd iRemote

# Generate the Xcode project from project.yml
xcodegen generate

# Build a Release binary
xcodebuild -project iRemote.xcodeproj \
           -scheme iRemote \
           -configuration Release \
           -derivedDataPath build/DerivedData \
           build

# The resulting bundle is at:
#   build/DerivedData/Build/Products/Release/iRemote.app
open build/DerivedData/Build/Products/Release/iRemote.app
```

If your project directory lives inside an iCloud-Drive-synced location, the FileProvider daemon may attach extended attributes to build outputs that make `codesign --verify` fail. The signature is still valid; the verification error is a metadata complaint. To dodge it, build into a non-synced location:

```sh
xcodebuild ... -derivedDataPath /tmp/iRemote-DerivedData build
```

## Running from an Xcode build

If you launch from an unbundled `iRemote.app` built into DerivedData, iRemote auto-detects the bundle's `Resources/` and finds the helper scripts there. No extra setup needed.

If you run from inside Xcode (with the binary at a non-standard path), iRemote falls back to `IREMOTE_PROJECT_ROOT` if set, then the current working directory. Set the env var in your scheme's Run action to the absolute path of `iRemote/Resources/` to be safe.

## Running tests

There is no automated test suite yet. The codebase has been hand-verified end-to-end. Contributions adding tests are welcome.

## Releasing a new version

1. Bump `CFBundleShortVersionString` in `project.yml`.
2. Regenerate: `xcodegen generate`.
3. Build: `xcodebuild -project iRemote.xcodeproj -scheme iRemote -configuration Release -derivedDataPath /tmp/iRemote-DerivedData build`.
4. Strip xattrs and ad-hoc sign (the `xattr -cr` step is harmless on a clean build but required if the bundle has been touched by Finder/iCloud):
   ```sh
   xattr -cr /tmp/iRemote-DerivedData/Build/Products/Release/iRemote.app
   codesign --force --sign - -o runtime --deep \
            /tmp/iRemote-DerivedData/Build/Products/Release/iRemote.app
   ```
5. Package as a `.dmg`:
   ```sh
   hdiutil create -volname iRemote -srcfolder /tmp/iRemote-DerivedData/Build/Products/Release/iRemote.app \
                  -ov -format UDZO iRemote-vX.Y.Z.dmg
   ```
6. Tag and push: `git tag vX.Y.Z && git push origin vX.Y.Z`.
7. Attach the `.dmg` to a new GitHub Release.

Notarization is not currently part of the release flow (the build is ad-hoc signed). For a notarized release, you'll need an Apple Developer account and `xcrun notarytool`. See Apple's docs.
